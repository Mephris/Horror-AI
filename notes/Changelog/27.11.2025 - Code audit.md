Consolidating scattered navigation logic and formalizing data split for the upcoming job system (HTN) architecture. 
### Code Audit & Foundation Cleanup

**Summary:** We completed the final structural cleanup before implementing the Job System. The core achievement is splitting the AI's "Interest" from its "Movement," which eliminates bugs caused by the AI confusing the object it cares about (a Table) with the spot it should walk to (the floor 3m away).

#### 1. The Core Data Split (Stalker Foundation)
* **Removed:** `public Transform currentPatrolTarget` (The single, obsolete target variable).
* **Added:** `public Transform currentInterestTarget` (The anchor point the Hunter is stalking, e.g., the Door object).
* **Added:** `public Vector3 currentNavDestination` (The coordinate on the floor the Hunter actually walks to).
    * **Impact:** The Behavior Tree can now process a target without being forced to walk directly onto its transform, enabling Vantage Point movement.

#### 2. Navigation Helper Consolidation
* **Logic Moved:** All scattered pathfinding and floor validation logic were moved into centralized helper functions in `HunterAI.cs`.
* **Result:** The AI now uses reliable, singular functions for movement checks, making future adjustments safer and preventing the reintroduction of the "Wall-Hack" and "Off-Mesh" bugs.

#### 3. Obsolete Variable Cleanup
* **Removed:** `public float doorwayMultiplier` and `public float wanderRange`.
    * **Rationale:** The Doorway multiplier is now handled organically by the **Momentum Multiplier** applied via the "Bridge" logic. The Hunter no longer performs random wandering.

## 🛠️ Description of New/Consolidated Functions

These are the functions that replace multiple lines of code in your Behavior Nodes and ensure consistent error handling across the system.
