### "Me of Tomorrow" Plan: The `ObserveAndScan` Node

This new node will be a "running" task that actively looks around, making the "Glance Perk" [cite: 12.11.2025, `FieldOfView.cs`] feel intentional.

**Core Logic for `ObserveAndScan`:**

1. **On Enter (Start of Node):**
    
    - Set `agent.isStopped = true`. This is **critical** to avoid breaking NavMesh pathfinding, as you noted. We will _only_ control rotation.
        
    - Start a timer (e.g., 5-10 seconds).
        
    - Get a list of all _other_ "hot" patrol points _in the same room_ (`activeGoal.targetRoom`).
        
2. **On Update (While Node is `RUNNING`):**
    
    - Find the closest "hot" point from this list (let's call it `scanTarget`).
        
    - **If `scanTarget` exists:**
        
        - Calculate the direction to `scanTarget`.
            
        - Smoothly rotate the Hunter's `transform.rotation` (using `Quaternion.Slerp`) to "look at" it.
            
        - **This is the key:** This active scanning will trigger `FieldOfView.cs` [cite: `FieldOfView.cs`] -> `Actions.HunterSawPatrolPoint` [cite: `Actions.cs`] -> `OnPatrolPointSeen` [cite: `HunterAI.cs`].
            
        - The "Glance Perk" [cite: 12.11.2025] will "cool down" the `scanTarget`.
            
        - Once the `scanTarget` is "cool" (e.g., `playerProbability <= baseUncertainty`), the node will pick the _next_ hottest point and turn to it.
            
    - **If no `scanTarget` exists (all points are cool):**
        
        - Perform a slow, generic 360-degree "room scan" (or just return `SUCCESS`).
            
3. **On Exit (Timer ends or all points scanned):**
    
    - Set `agent.isStopped = false`.
        
    - Return `SUCCESS`, so the BT loop can move to the next `MoveToPatrolPoint`.
